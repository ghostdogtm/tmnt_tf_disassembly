# Teenage Mutant Ninja Turtles: Tournament Fighters (NES, U) — disassembly

[Українська версія](README.uk.md)

ca65 sources that assemble byte for byte into
`Teenage Mutant Ninja Turtles - Tournament Fighters (U) [!].nes` (Konami, 1993; mapper 4 / MMC3, 128 KB PRG,
128 KB CHR). The sources in `src/` are **generated**: names, comments, constants and data formats come from three
hand-edited label files in `tools/labels/`, and `tools/disasm.py` writes the sources and checks the result against
the original ROM.

The ROM is not included. Put your own dump (and the CDL that comes with this project) in the project root.

## Quick start

You need `ca65` / `ld65` (cc65 V2.19 was used) and Python 3 (3.13 was used; `tools/frames_png.py` also needs
Pillow) in PATH. The project root must hold:

| file | |
|---|---|
| `Teenage Mutant Ninja Turtles - Tournament Fighters (U) [!].nes` | **your own** dump of the game (not in the repository, see below) |
| `Teenage Mutant Ninja Turtles - Tournament Fighters (U) [!].cdl` | Mesen 2 code/data log of the game (in git) |

**The ROM is not in the repository, and neither are the graphics.** Put your own dump into the project root under the
name above. Expected: 262 160 bytes (16-byte iNES header + 128 KB PRG + 128 KB CHR), CRC32 `AC05464F`, SHA-1
`182f901142530a509a7c9f5831b5a7f7f4c923a8`. Check it with

```powershell
python tools/check_rom.py
```

`tools/disasm.py` runs the same check first and stops with a message if the file is missing or is another dump. The
CHR graphics (`src/chr/`, `gfx/`) are cut out of your ROM during the build, so they never need to be committed.

```powershell
python tools/disasm.py --build
```

This generates `src/`, `config.cfg`, `assemble.bat` and `compare.bat`, splits the CHR ROM into `src/chr/`, assembles
`game.nes` and prints `build: IDENTICAL` when the result matches the original. Run it once after a fresh checkout:
`src/chr/` is not in git.

After that, the sources can be assembled without the generator:

| | Windows | make (Linux, macOS, Windows with make) |
|---|---|---|
| assemble `game.nes` | `.\assemble.bat` | `make` |
| assemble and compare with the original | `.\compare.bat` | `make check` |
| all checks | — | `make test` |
| regenerate `src/` from the label files | `python tools/disasm.py --build` | `make gen` |

On Windows, quote paths: the folder name may contain `!` and spaces. Set `PYTHONIOENCODING=utf-8` if a tool fails
to print a character in the console.

## Layout

```

src/prg/BB_name.asm      one file per module (84 files, 8 KB banks split by subject; docs/modules.md)  (generated)

src/defines.inc          hardware registers, unresolved raw symbols (generated)

src/const.inc            constants, enums, structs                  (generated from tools/labels/const.txt)
src/charmap.inc          .charmap macros of the game fonts          (generated)
config.cfg               ld65 memory map: header, 16 PRG banks, CHR (generated)
tools/labels/rom.txt     ROM labels and directives                  (hand-edited)
tools/labels/ram.txt     RAM names                                  (hand-edited)
tools/labels/const.txt   constants and per-instruction uses         (hand-edited)
tools/labels/banks.txt   bank-pair hints seen in Mesen runs         (generated by tools/mesen/merge_runs.py)
tools/mesen/cdl/bot.cdl  extra CDL from the Mesen bot runs          (merged with the game CDL)
tools/*.py               generator and checks (see below)
docs/                    data formats, coverage and cross-reference reports
gfx/                     PNG pictures of the CHR banks and fighter frames (generated, not in git)
```

## How it works

`tools/disasm.py`:

1. Reads the ROM and every CDL (the game's CDL and `tools/mesen/cdl/*.cdl`, Mesen 2 `CDLv2` or FCEUX) and marks
   each PRG byte as code, operand or data.
2. Traces code the CDL missed from known code and from `entry` lines (marked `T` in the line comments), follows
   jump tables after `JSR JumpTable` (D032, `dispatch` lines), detects `.word` tables, RTS-trick tables and lo/hi
   pairs.
3. Resolves every `$8000-$BFFF` operand to a bank (see [banking](#hardware-and-banking)), names targets
   (`sub_`/`loc_`/`dat_` when there is no user label), turns references inside a routine into local `@labels`.
4. Decodes the known data formats (text, screens, metasprites, move scripts) and substitutes constants.
5. Writes the sources and `game.mlb` (Mesen labels), assembles, and compares with the original ROM.

Every source line keeps a comment with the CDL flags, the file offset, `bank:address` and the bytes:

```
  LDA objJumpVelX,X               ;C-J- 04777 02:8767: BD A0 04
```

Flags: `C` code, `D` data, `J` jump target, `S` subroutine entry, `T` traced (not in the CDL); `-` none. Bytes that
no CDL saw read are marked `unread`.

The loop is always: **edit `tools/labels/*.txt` → `python tools/disasm.py --build` → `IDENTICAL`**. Never edit
`src/` by hand; the next run overwrites it.

## Label files

The full syntax is in the docstrings of `load_rom_labels` and `load_consts` in `tools/disasm.py`. Addresses are
`BB:AAAA` (bank : CPU address) in the switchable banks 00-0D and plain `AAAA` in the fixed banks ($C000-$FFFF).
A `(?)` in a comment marks a guess that was not verified.

**ram.txt**: `ADDR name [SIZE] ; comment`. With SIZE > 1, `ADDR+n` is written as `name+n`.

**rom.txt**: `LOC name ; comment` plus directives:

| directive | meaning |
|---|---|
| `code` / `data` / `words` / `rtswords RANGE` | force the classification (rtswords: stored address = target − 1) |
| `table RANGE N` | data table, N bytes per row |
| `numwords` / `dbyt RANGE` | 16-bit numbers, little / big endian, not addresses |
| `split LOC LOC N` | lo / hi address tables |
| `imm LOC LOC` | the immediates of two instructions are `#<target` / `#>target` |
| `ref LOC Name±N` | the operand of the instruction at LOC is written as `Name±N` (checked) |
| `alias RANGE RAM[/N] name` | inside the code range the RAM bytes get another name |
| `bitskip LOC` | `BIT abs` ($2C) used to skip the next 2-byte instruction |
| `entry LOC` | code with no known caller: trace from here |
| `dispatch LOC` | the routine pops its return address and jumps through the inline `.word` table after the `JSR` |
| `bank LOC TT`, `bankcall LOC TT`, `rawsym AAAA name` | banking hints (below) |
| `text`, `charmap`, `screens`, `screentext`, `metasprites`, `movescripts`, `aiscripts`, `sound`, `soundptrs`, `framenames` | data formats (see [docs](#data-formats)) |
| `note LOC ; text` | a comment line before LOC |
| `module LOC name` | start a new source file at LOC |

**const.txt**:

| line | meaning |
|---|---|
| `NAME = EXPR [@var ...]` | constant. `@var` binds it to a RAM variable: it replaces the immediate wherever that value is stored into, loaded from or compared with the variable |
| `use LOC [LOC ...] EXPR` | the immediate of these instructions is EXPR |
| `data LOC EXPR, ...` | data bytes written as expressions |
| `enum` … `endenum` | an anonymous `.enum` |
| `struct Name field[:size] ...`, `array var Name` | `.struct` for arrays of records in RAM |

Every expression is checked against the real byte, so a wrong name fails the build instead of producing a wrong
source.

## Hardware and banking

- **PRG**: 16 banks of 8 KB in MMC3 PRG mode 0. The game always maps the switchable banks in pairs (R6 = n,
  R7 = n + 1, n even), so every bank has one CPU address: even banks 00-0C at $8000, odd banks 01-0D at $A000,
  bank 0E at $C000 and 0F at $E000 (fixed). Every even bank starts with its own number; `$8000` is read to find the
  pair that is mapped (`rawsym 8000 BankIdAt8000`).
- **Bank stack**: far calls push the current pair on `bankStack` (`$3D`/`$3E`), map another one and pop it back
  (F5DF-F5F3, one entry point per pair; `bankcall` lines). Sound runs in pair 00/01 (`MapSoundBank` F669).
- An operand `$8000-$BFFF` in the switchable banks refers to the pair the code is in. In the fixed banks it needs a
  hint: `bankcall` (the code after `JSR` to a bank-mapping routine), `bank` lines in rom.txt or the generated
  `tools/labels/banks.txt` (the pair seen when Mesen ran that instruction). Without a hint the operand would stay a
  number; there are none left (`docs/coverage.txt`: unresolved 0).
- Code crosses the even/odd boundary inside a pair (e.g. a `JSR` at 0A:9FFF), so the generator treats a pair as one
  16 KB unit.
- **CHR**: 128 KB, switched in 1 KB / 2 KB banks; the shadows of R0-R5 are `chrBanks` ($32-$37).
- **IRQ**: the MMC3 scanline IRQ (F85E) splits the screen; `SetIrqSplit` (F814) picks the handler and the scanline.
- Vectors: NMI F219, RESET F174, IRQ F85E.

## What is known about the game

A short map; the details are in the label files (search the names) and in `docs/`.

- **Game modes**: `gameMode` ($20) is dispatched by `RunGameMode` (F380, table at F389): `MODE_TITLE`, `MODE_DEMO`, `MODE_GAME`
  (player select and fights), `MODE_KONAMI`, `MODE_LEGAL`, `MODE_OPTION`, `MODE_INTRO`, `MODE_ENDING` (?). Inside a
  fight, `modeSubState` steps through stage load, round setup, intro, running, round over, KO pause, match over.
- **Title menu** (`gameType` $2C): story, VS player, VS CPU, tournament, option. Options: difficulty ($0125), game
  speed ($0126, turbo shortens moves and jumps), timer ($0127).
- **Objects**: 16 slots, field arrays at `$0400 + $10 × field` (`objFrame`, `objY`, `objX`, velocities, `objState`,
  `objPhase`, `objTimer`, `objBox`, `objPower` …). Slots 0/1 are the fighters, 2-5 their attack objects, 6 the ball.
- **Fighters**: `objSpriteSet` = character (`CHAR_*`: Leo, Raph, Mike, Don, Casey, Hothead, Shredder), `objState` =
  `FST_*` (stand, jump, hurt, crouch, special move, hold …), HP in `fighterHp` ($0590, $B0 = full).
- **Joypad**: `joyPressed` / `joyHeld` ($8E / $91, `BTN_*`). The CPU fighter plays by writing these for its pad
  (CPU AI in bank 0A and EC5B-EF60, [docs/ai.md](docs/ai.md)).
- **Sound** (driver in banks 00/01, `SoundStart` 00:8E8D): ids below `SND_MUSIC` ($2E) are effects (`SfxPtrs`),
  $2E-$46 music (`SongPtrs`, 4 channels), $47-$5A DPCM samples (`DpcmSamples`, 5 bytes each; voices in bank 0E),
  $5B fades the music out. Streams, channels and envelopes: [docs/sound.md](docs/sound.md).
- **PPU queue** ($0300, run by `RunPpuQueue` in the NMI): command, address; rows, columns, fills and sequences.

## Known bugs in the game

- **Casey's second distance check never filters** (CPU AI, bank 0A, `0A:9619` and `0A:96B2`). `AbsDeltaBelow` starts with
  `TAY`, so Y holds its limit ($50) when Casey calls `ObjDeltaY16` again; the routine then reads `objVelY[0] - objY,X`
  instead of the vertical gap to the target. The "A only while $30 <= |dy| < $50" band therefore never applies and the CPU
  Casey presses A for every |dy| < $50. Checked with exact values in Mesen and with a patched register (not a patched
  ROM): [docs/ai.md](docs/ai.md). A scan of all call sites of `AbsDeltaBelow` and of the other routines that leave X/Y
  changed found no second case; the scan does not follow branches.
- **A per-character table is read with the fighter slot** (`StartAttackIdleState`, `02:8352`). `AttackIdleTimeByChar`
  has one entry per character, but the code does `LDY objSpriteSet,X` and then `LDA table,X`, so X (slot 0 or 1) is the
  index: P1 always gets 4, P2 always 3, and the other five entries are never read (they show up as unread in the CDL).
  Confirmed in Mesen: with both fighters set to Don (table entry 3 = 4) slot 0 got 4 and slot 1 got 3.
- **`GetBallRange` uses a stale value** (`EEB9`). The half of `|aiTargetDx|` is built into `tmp04`/`tmp04+1` only
  when `aiTargetDx` is negative; for `aiTargetDx >= 0` the previous contents are compared with the ball distance. Mesen
  (Story run, 1 295 calls): `tmp04` pair was $00/$02 in 990 of the 1 007 calls with `aiTargetDx >= 0` while the value
  changed; with a negative value it is exactly `|aiTargetDx|`.
- **`AiTargetAttacksMe` reads the wrong byte for target slot 1** (`ED6B`). `LDA aiTargetDx,Y` uses the target slot as
  the index into the 2-byte `aiTargetDx`, so for the AI on slot 0 it takes the low byte and tests its bit 7: right only
  while the gap is under 128 pixels. Found by reading; Mesen showed 51 calls with X = 0, Y = 1 in the demo, but the
  moving-target branch itself was not reached.
- **`AiStepScript` tests slot 0's jump step** (`0A:81C2`). In the "jumping, close range: press A" test the code does
  `LDA objStep` without `,X`, so for the CPU fighter on slot 1 it reads fighter 0's step. Mesen (Story run, 14 000 frames,
  32 passes of the A branch): three times fighter 1 was in `FST_JUMP` with its own `objStep` = 2 while fighter 0's was 1,
  and the CPU pressed A anyway; the AI on slot 0 is not affected.

- **`AiShredderNearHurtPick` indexes a 4-entry table with 0-7** (`0A:9AE5`). `AiShredderHurtActs` has four entries,
  but the code calls `AiRandom8`, so half of the picks read the bytes that follow the table. Found by reading; not
  measured in Mesen.

## Fixing the bugs (optional patches)

The disassembly always rebuilds the original, bug for bug. Each bug above has an independent byte patch in
[tools/patches.py](tools/patches.py); [tools/patch_rom.py](tools/patch_rom.py) applies chosen ones to a copy of the ROM
(the source is never changed, every edit checks the original bytes first):

```
python tools/patch_rom.py --list                    # numbers, names, descriptions
python tools/patch_rom.py --all                     # game_fixed.nes with every patch
python tools/patch_rom.py --only 1,3,ball-range     # chosen ones (numbers or names)
python tools/patch_rom.py --except 2                # everything but these
make fixed PATCHES=all | 1,3 | -2,6                 # same through make (a leading - means "all except")
```

| # | Name | Bug | Edit |
|---|------|-----|------|
| 1 | `casey-dy-gap` | Casey's second distance check | two JSR operands in bank 0A go to a 7-byte stub at `0F:EF61` (`JSR AbsDeltaBelow; LDY aiTarget,X; RTS`) |
| 2 | `attack-idle-time` | `AttackIdleTimeByChar` indexed by slot | `02:8352` `LDA table,X` -> `LDA table,Y` (1 byte) |
| 3 | `ball-range` | `GetBallRange` stale value | `0F:EEEE` jumps to a 39-byte stub at `0F:EF68` that fills `tmp04` for both signs |
| 4 | `target-attacks-me` | `AiTargetAttacksMe` wrong byte | `0F:ED6B` `LDA aiTargetDx,Y` -> `LDA aiTargetDx` (1 byte) |
| 5 | `step-script-objstep` | `AiStepScript` slot 0's step | `0A:81C2` `LDA objStep` -> `LDA objStep,X` (1 byte) |
| 6 | `shredder-hurt-acts` | 4-entry table, 0-7 index | `0A:9AE6` `JSR AiRandom8` -> `JSR AiRandom4` (1 byte) |

The stubs live in the unused `$FF` fill at `0F:EF61-EF8F`, at fixed addresses, so any combination works. All patches
were applied together to a ROM and run for 12 000 frames of a Story fight in Mesen (stubs 1 and 3 were reached, the game
ran on); the effect on gameplay was not measured. The patches only touch the CPU AI (and patch 2 the idle time of both
players), so nothing else changes.

## Mesen tools

`tools/mesen/` runs Mesen 2 headless (`--testrunner` with a Lua script) to log what the game executes and reads.
The scripts run the project's own Mesen copy (default `./mesen`, not in git) in place and patch its `settings.json`
(Lua IO on, RAM zeroed at power on), so do not point them at the Mesen you play with. Run one instance at a time.

| tool | |
|---|---|
| `run_mesen.py` + `explore.lua` | a bot that walks the menus and plays (story, VS, options, demo); logs executed / read bytes, bank pairs, RAM writes, optional screenshots; `--cfg` sets Lua fields (held RAM values, scripted input) |
| `merge_runs.py` | merges the runs into `tools/mesen/cdl/bot.cdl` and `tools/labels/banks.txt` |
| `new_code.py` | PRG bytes a run reached that the CDL never saw |
| `montage.py` | contact sheet of screenshots |
| `run_log.py`, `rom_read_log.lua`, `gen_sites.py`, `merge_logs.py` | indexed-read logger carried over from another project (Mighty Final Fight); not adapted to this layout (?) |

## Status

- The build is byte-identical; lint, relocation test and self-test pass.
- Coverage (`docs/coverage.txt`): every PRG byte is code, data or a word table, except 36 000 bytes of `$FF` fill
  (banks 07, 08, 09, 0B, 0D are mostly empty).
- Names: about 3 000 named labels, 302 RAM names, 1 194 constants; no `sub_`/`loc_`/`ram_`/`dat_` names are left (a few table names carry `(?)` until verified in the emulator). Sound streams (`Sfx<id>`, `Mus<id>_<channel>`, `Env<n>`, `_P<n>` for called parts) and metasprite frames (`TurtleFrame<n>` … via `framenames`) are named by the generator from their tables. Branches are named by meaning where the code shows it; the rest by structure
  (`...StepN` = jump-table entry, `...Rts` = RTS exit, `Goto...` = JMP-only label); 1 967 numeric immediates
  (832 of them plain 0 / 1 / $FF, the rest mostly masks) are left.
- Decoded data formats: text, screens, fighter metasprites and CHR banks, animations, move scripts, attack objects,
  special moves, CPU AI action scripts and decision trees, music and sound effect streams, envelopes.
- Not decoded yet: the effect of a few sound commands (`SC_SLIDE` and the echo bits were read from the code, never heard; see
  docs/sound.md) (the CHR banks, palettes and a screenshot of each arena are in docs/screens.md, Arenas). Names and guesses marked `(?)` are not verified.
